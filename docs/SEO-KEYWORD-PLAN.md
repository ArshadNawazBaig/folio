On October 5, we ran **28 web searches, one for each tool**, and opened the first returned page for every query. We also reviewed iLovePDF, Sejda, Adobe, iLoveIMG and Invoice-Generator.com as established product benchmarks, and Google's own search guidance.

The [28-row competitor research CSV](SEO-COMPETITOR-RESEARCH.csv) records the exact query, date, reviewed URL, two additional returned URLs, practical opportunity and product limitation for every tool. Search-provider ordering is an observed snapshot. It is **not** an independently verified Google position, a country-specific top-three report, a search-volume estimate or a keyword-difficulty score. Provider claims were read, not performance-tested. Some results came from smaller publishers; their appearance does not prove authority or a successful business.

Refine the map with the supplied Search Console observations and future page-filtered queries. These artifacts separate research observations from our implementation choices.

## Analyze actual Search Console exports for free

Use the English Search Console interface, open **Performance → Search results**, choose a single date range (no comparison), and enable clicks, impressions, CTR and average position. Export CSV; the downloaded ZIP can be used directly. Record the property, dates and active filters. [Google's report/export documentation](https://support.google.com/webmasters/answer/7576553?hl=en)

```sh
npm run seo:opportunities -- /path/to/search-console-export.zip \
  --period 2026-09-07:2026-10-04 \
  --context "thebestfreepdf.com; Web; all countries; all devices; no page/query filters" \
  --output /tmp/folio-search-opportunities.json
```

Replace the dates and context with the actual export scope. Separate `Queries.csv` and `Pages.csv` paths also work. The analyzer runs locally, requires no API key or subscription, and refuses to overwrite existing output or input files.

It flags existing visibility to investigate, visible rows without clicks, possible branded queries and rows with limited observations. Its default 20-impression threshold and position bands are transparent editorial heuristics, not proven Google cutoffs or forecast wins. Use `--min-impressions` to change the review threshold. It calculates CTR from observed clicks/impressions and treats zero/absent position as unavailable.

Page and query tables stay separate: global exports cannot prove which query belongs to which page. Check the corresponding filtered view in Search Console before editing. The analyzer does not add table rows into supposed site totals or infer that missing rows mean no indexing. Original source data stays private; reports contain the supplied query/page data and should not be committed as public research.

The source folder now contains `opportunities-2026-10-05.json`, `baseline-analysis-2026-10-05.json` and a readable `search-console-review-2026-10-05.html`; none is committed. Unit tests still use synthetic fixtures to verify parser behavior, not to claim traffic results.

The chart totals reconcile with country/device totals. Page impressions use a different aggregation and should not be substituted for site totals. The query table covers only a fraction of the observed clicks; it cannot identify the searches behind the remainder. Country data cannot distinguish the owner from other visitors. The empty search-appearance table does not prove a structured-data error. [Google's dimensions and data grouping explanation](https://support.google.com/webmasters/answer/17011259?hl=en)

## Implementation in this checkout

- Individual titles/descriptions for all 28 tools, crawlable homepage discovery across six categories, and related links connecting plausible next tasks.
- An original practical example on **every English tool page**, rendered in the initial HTML. Each describes a scenario, settings, an output check and a real product limit.
- Five new downloadable practice assets: a sideways-page PDF, an unnumbered PDF with a cover, a fictional JPG receipt, a PNG screenshot and a transparent WebP graphic. Three earlier practice PDFs are reused where appropriate.
- The examples sit below the usable tool and brief instructions. They add no client-side JavaScript dependency or new paid service. File bytes download only when a visitor follows a sample link.
- The existing English mobile-editing guide now gives device-specific steps, original-text editing instructions, a practice task and download troubleshooting. Its visible date, structured data, sitemap and feed share the actual revision date. Existing translations keep their reviewed edition and date.
- All existing localized routes, metadata and discovery links remain. The new editorial examples are English only until reviewed translations are available; they are not silently inserted as English into other languages.

The samples are original, contain no customer information, and can be used, modified and shared. Recreate the new assets with `node scripts/generate-tool-samples.mjs`. Their purpose is to help people check actual behavior, not to create indexable filler files. Avoid promising OCR, AI upscaling, permanent hosted short links, certified signing, or strong image-based PDF compression that the code does not provide.

Changes are local until the release is deployed and verified. Search engines cannot evaluate unpublished changes.

## Search Console decision rules

Search Console counts Google Search impressions and clicks. It is not a count of every site visitor or of direct/social referrals. No new analytics subscription is required for this plan. If future referral analytics are needed, choose a separate implementation deliberately.

For each tool, record: URL, inspection date, indexing state/reason, selected canonical, period, clicks, impressions, CTR, average position, country/device filters and one next action.

| Evidence                                  | Next action                                                                                                                                                                              |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Not indexed                               | Read the exact reason. Resolve a blocking directive, duplicate/canonical issue, server failure or weak/duplicated content as applicable; do not assume every exclusion has the same fix. |
| Indexed, no impressions                   | Confirm the task matches the page, keep clear internal links, make a useful demonstration and earn relevant discovery. Check the reporting period before concluding the page failed.     |
| Relevant impressions, few clicks          | Inspect the query, device and position. Improve unclear titles/descriptions when appropriate; a low position can explain low CTR.                                                        |
| Two URLs appear for the same query        | Check whether they serve different needs. Keep a tool for doing the task and a guide for instruction; improve linking before considering a merge or redirect.                            |
| Clicks, but users report failed downloads | Prioritize the product failure. More copy will not fix an unusable tool.                                                                                                                 |
| Unrelated queries                         | Adjust wording to clarify the supported task; do not add nonexistent features to match the traffic.                                                                                      |

Review weekly rather than reacting to daily noise. Use nonbranded queries separately from searches for “Folio” or the domain. Compare the six tool groups as well as individual pages. Average position varies by query/context and is not a fixed universal rank. Do not add overlapping group totals.
