# Search visibility review — September 17, 2026

Preferred origin: **https://thebestfreepdf.com**. Brand: **Folio**.

## Findings and changes

- The initial live audit passed for all 49 sitemap URLs. HTTPS, canonicals, robots, real 404s, social metadata, and private-route noindex were already working. Google Search Console's earlier “Couldn't fetch” report remains a separate diagnostic: a successful fetch from this machine does not prove Google has processed the sitemap.
- `/tools?page=2` and `/convert?page=2` repeated page-one titles and descriptions. Shared listing metadata now describes each page separately. Blog filters share one parser between metadata and rendering, preserve their filters in the canonical URL, and safely normalize repeated or invalid query parameters. Search and alternate-page-size results remain noindex but allow following their links.
- The expanded live crawl found identical descriptions on JPG to PDF, PNG to PDF and Merge images. Each now describes its accepted formats and purpose separately, in both visible copy and metadata.
- Browser regression coverage exposed a second canonical link from a previous filtered blog listing arriving after navigation to an article. Metadata streaming is disabled so metadata resolves in the document head. Page-one pagination links now use the base URL without a redundant `page=1` parameter.
- Tool, converter, blog and guide directories now describe their visible entries with CollectionPage/ItemList data. Pagination positions match the displayed records. Organization markup uses the actual 512px brand mark. No ratings, reviews or rich-result promises were invented.
- Tool recommendations and related guides previously chose the first few catalogue entries. They now prioritize shared tasks and primary tools; unavailable tools are excluded from recommendations.
- Published blog articles now include crawlable section navigation, a visible update date when different from publication, editorial attribution links, and links to working tools explicitly referenced in the article. The guide and blog headings now describe their subject directly.
- Added an original troubleshooting guide at `/guides/why-cant-i-edit-pdf-text`, covering scans, outlines, fonts, supported text blocks, and the distinction between save errors and extraction problems. It links to the relevant tools and states current OCR and paid-export limitations. Existing free/paid entitlements are unchanged.
- Homepage sample-editor links no longer prefetch the editing route. Blog covers use responsive Next.js images for the public blog bucket and Unsplash; other permitted CMS URLs retain their original source. No private document bucket is allowed into the image optimizer.
- The first blog thumbnail and article cover load eagerly; later thumbnails remain lazy. Low-contrast blog counts and reading-time labels were darkened after mobile accessibility checks.
- `/favicon.ico` and legacy Apple touch-icon requests previously returned 404. Icons now derive from the existing Folio SVG, with browser sizes, Apple touch icon, and 192/512px manifest icons. Regenerate them with `node scripts/generate-brand-icons.mjs`.
- The deployment audit now follows directory pagination, checks duplicate descriptions, looks for orphan sitemap pages, and verifies icon/social-image responses. `npm run test:seo` runs the SEO and blog browser checks against synthetic local data.
